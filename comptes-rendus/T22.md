## Page 2 — Explorer

- Nouvelle page, donc pas de capture « avant ». Captures « après » (début de page) :
  `captures/T22-2-explorer-1366.png`, `captures/T22-2-explorer-420.png`.
- Une **grille de cartes**, une par dossier des trois chaînes, du plus urgent au moins urgent.
  Chaque carte porte :
  - sa photo, déjà masquée par T17 ;
  - sa famille (dépotoir, fuite, nuisance) et son étape ;
  - son quartier et sa date ;
  - sa note d'urgence et ses raisons.

  Une carte sans photo garde la même hauteur (cadre 4:3, 16:9 sur téléphone, avec
  « Pas de photo »).
- **Filtres** par nature, par étape (par défaut : les dossiers ouverts) et par quartier,
  appliqués sans recharger. Essayés un par un dans le navigateur :
  ```
  départ 19 sur 20 · fuites 2 · fuites + Dapoya 1 · Dapoya 2 · sans quartier 14 ·
  effacés 19 · toutes étapes 20 · collectés 1 — 0 erreur
  ```
- Les listes ne contiennent pas les photos : chaque carte va chercher le détail de son dossier
  **quand elle apparaît à l'écran**. La page reste ainsi légère même avec des centaines de
  dossiers.
- **Limite** : les dépotoirs n'ont pas de quartier (absents de l'extrait OpenStreetMap). Le
  filtre « Quartier » ne vaut donc que pour les fuites et les nuisances, et « Non précisé »
  regroupe les dépotoirs.
- « Explorer » est ajouté aux sections de la barre.

## Page 3 — Détail d'un signalement

- Nouvelle page : `signalement.html?type=depotoir|fuite|nuisance&id=…`. Captures :
  `captures/T22-3-detail-1366.png`, `captures/T22-3-detail-420.png`.
- Ce qu'elle montre :
  - la **galerie** : une grande photo, des vignettes, la date et le nombre de visages ou
    plaques masqués ;
  - les **informations** propres à chaque chaîne (volume, superficie et dépôt ; ampleur et
    référence ONEA ; nature, gravité et service) ;
  - l'**avertissement** si la position vient d'un lieu connu (T16) ;
  - le **message vocal** ;
  - ce qu'ont **écrit** les habitants ;
  - la **note d'urgence avec ses raisons** ;
  - l'**historique** (le journal du dossier) ;
  - les **actions** de l'étape.
- Actions : mêmes appels que les postes de travail (`POST …/avancer` avec ce qui a été
  constaté, `POST …/classer` avec un motif, `DELETE /api/dossiers/<id>/identites`).
  - « Avancer » n'apparaît que pour le poste attendu, « Classer sans suite » que pour la mairie.
  - Le motif de classement se tape dans la page et non dans une boîte `prompt()`. Il est
    exigé : sans lui, la page le dit et n'envoie rien.
  - Le serveur contrôle de toute façon les droits.
- L'identité du déclarant n'apparaît que si le serveur la renvoie (agent connecté).
- La note d'urgence n'est pas dans la réponse du détail : elle est reprise de la liste de la
  même chaîne, pour être exactement celle des postes de travail. C'est une lecture de plus,
  pas une adresse nouvelle.
- Essayé dans le navigateur :
  ```
  dossier témoin : photos 4 (grande + 3 vignettes), message vocal 1, témoin affiché ;
  commentaire « <script>alert("piège")</script> derrière le mur » affiché comme du texte,
  aucun <script> dans la page ; « Classer » sans motif → « Écrivez d'abord pourquoi… » ;
  fuite et nuisance : leurs informations propres ;
  « Confirmer sur le terrain » sur un dossier signalé → « Confirmé », l'historique le montre ;
  adresses fausses (id inconnu, type inconnu, id non numérique) → message clair ;
  0 erreur JavaScript, 0 boîte de dialogue.
  ```
- Vérifications avant le commit : `pytest` **212 passed, 1 skipped** ; parcours **27 réussies,
  0 en échec** (dont la page de détail à 1366 et 420 px).

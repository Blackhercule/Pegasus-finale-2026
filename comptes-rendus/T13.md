# T13 — fait (cloud) — 16/11 18 h 55

> ## ⚠️ À retenir pour la démonstration
> **Le jury devra se connecter pour voir la carte, le plan, les scénarios et les dossiers.**
> L'équipe doit avoir sous la main, le jour J, l'identifiant `agent` et son mot de passe
> (`AGENT_MOT_DE_PASSE` dans le fichier `.env` du PC, tiré par `installer.sh`).
> Le signalement (`/signaler/`) et l'envoi de lots par le jury restent ouverts sans connexion.

- Session : dans le cloud (conteneur Linux). Rien n'a tourné sur le PC : à revérifier sur le PC
  avec T11.
- Réalisé : un filtre unique, appelé avant chaque requête, ferme tout sauf une liste blanche ;
  une page `interface/decision/connexion.html` (+ `.js`, `.css`) servie à la place de toute page
  protégée demandée sans session ; tests `tests/test_acces.py`.
- Vérification :
  ```
  $ python -m pytest -q
  142 passed in 153.08s
  ```
  (49 de ces tests sont nouveaux, dans `tests/test_acces.py`.) Contre-épreuve : en désactivant
  le filtre, `test_aucune_route_n_est_ouverte_par_oubli` échoue bien.
  Dans Chromium (Playwright), avec les vraies données de Ouagadougou :
  ```
  1. /decision/scenarios.html sans session : page de connexion affichée
  2. mauvais mot de passe : refusé, message affiché
  3. après connexion, on arrive sur /decision/scenarios.html
  4. /decision/ : la carte (canvas MapLibre) s'affiche
  5. /signaler/ sans connexion : 200
  6. depuis /signaler/ : envoi d'un signalement → 201 ; lecture des dépotoirs → 401
  7. requêtes hors de la machine : 0 ; erreurs JS : 0
  ```
- La liste blanche exacte (`OUVERT_A_TOUS`, dans `application/__init__.py`) :

  | Fonction Flask | Adresse |
  |---|---|
  | `page_signaler` | `/signaler/…` (page, script, style, `service-worker.js`, manifeste, sons) |
  | `bibliotheques` | `/vendor/…` (la page de signalement y charge sa police) |
  | `recevoir` | `POST /api/signalements` |
  | `recevoir_lot` | `POST /api/signalements/lot` |
  | `fichier_joint` | `/api/fichiers/…` — `public/` ouvert ; `prive/` exige toujours une session (inchangé) |
  | `connecter`, `session_en_cours`, `deconnecter` | `/api/connexion`, `/api/session`, `/api/deconnexion` |
  | `page_decision`, seulement pour `connexion.html`, `connexion.js`, `connexion.css` | la page de connexion elle-même |

  Tout le reste demande une session, y compris `/` (qui sert encore la carte : T12 la remplacera
  par l'accueil public), `GET /api/signalements` (la liste) et `/donnees/…` (fond de carte et
  fichiers de la commune, que seule la partie décision utilise).
- Comment ça marche :
  - `filtrer_l_acces()` regarde le nom de la fonction Flask qui va répondre (`request.endpoint`).
    S'il est dans la liste blanche, ou si la session contient un agent, la requête passe. Sinon :
    une adresse `/api/…` reçoit `401 {"erreur": "Connexion requise."}`, que les pages savent déjà
    traiter ; une page reçoit la page de connexion, avec le code 401, **à la même adresse**.
  - Après un mot de passe accepté, la page de connexion recharge simplement l'adresse : on
    arrive sur la page demandée. Il n'y a pas de paramètre « revenir à… » qu'un tiers pourrait
    détourner vers un autre site.
  - Liste blanche plutôt que liste noire : une route ajoutée demain est fermée tant qu'on ne
    l'a pas ouverte exprès. Le test `test_aucune_route_n_est_ouverte_par_oubli` appelle chaque
    route de Flask sans session et échoue si l'une d'elles répond autre chose que 401 sans être
    dans la liste blanche.
  - Rien de nouveau côté comptes : mêmes comptes de `.env`, même session Flask signée, même
    jeton anti-CSRF ; `@agent_requis` filtre toujours par poste pour les actions.
- Composants ajoutés : aucun.
- Décisions :
  - Le filtre se fonde sur le nom de la fonction Flask et non sur l'adresse : la méthode est
    comprise dedans (`POST /api/signalements` est ouvert, `GET /api/signalements` ne l'est pas).
  - Tout poste connecté (mairie, brigade, collecte, ONEA) voit la partie décision ; les droits
    d'agir restent ceux de `@agent_requis`.
  - Tests existants : 30 lisaient les données sans connexion. Ils se connectent maintenant via
    le fixture `agent` déjà présent. Les trois tests « l'identité du déclarant reste cachée du
    public » vérifient désormais que le public reçoit 401 (plus strict qu'avant).
- À savoir :
  - **Le jury doit se connecter** (voir l'encadré en tête).
  - La page de connexion a son propre style, volontairement simple ; T14 l'habillera.
  - Point ouvert, hors de cette tâche : `POST /api/connexion` n'a aucune limite d'essais. Un
    jury de cybersécurité pourrait essayer des mots de passe en boucle ; les mots de passe tirés
    par `installer.sh` sont longs, mais un compteur d'échecs serait une bonne parade.
